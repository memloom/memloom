## Overview

The connector syncs pages you choose into memloom as context documents, recallable alongside your
memories and files, and keeps them fresh. No extraction, so sync costs only embeddings, and only
for content that changed.

<Steps>
  <Step title="Create an integration" icon="key">
    At [notion.so/profile/integrations](https://notion.so/profile/integrations).
  </Step>
  <Step title="Share your pages with it" icon="share-nodes">
    Page menu, then Connections. Access recurses, so sharing a page includes its subpages and
    database rows.
  </Step>
  <Step title="Add the token" icon="file-pen">
    `NOTION_TOKEN=...` in `~/.memloom/config.env`, then restart the daemon.
  </Step>
</Steps>

***

## notion connect

```bash
memloom notion connect                   # interactive picker
memloom notion connect --page Diary      # by title or id, repeatable
memloom notion connect --all             # everything the integration can see
```

The picker shows the workspace as a tree. Subpages and databases indent under their parent, and
database rows collapse into a row count. Syncing a database captures every row; a specific row
with body content is still selectable with `--page`.

***

## notion sync

```bash
memloom notion sync
memloom notion sync --dry-run   # list what would sync, no content fetches
memloom notion sync --force     # ignore every cache and refetch in full
```

Pages become markdown documents: toggles flattened, to-do state kept, tables as pipe rows. The
daemon also polls every 5 minutes, so edits land without you running anything.

| Level | How it saves work |
| --- | --- |
| Change detection | Asks each page directly rather than trusting Notion's search index, so a fresh edit is never missed. An idle workspace costs one call per poll |
| Section refetch | Only sections whose `last_edited_time` moved are re-downloaded. Editing one day in a 494-day diary refetches one section |
| Chunk reuse | Unchanged chunks keep their row, embedding, indexed state and entity links |

A page-level change that no section accounts for falls back to a full fetch, so nothing slips
through. A manual sync arriving mid-poll waits its turn rather than being refused.

***

## notion status and disconnect

```bash
memloom notion status        # token, selection, last sync, synced documents
memloom notion disconnect    # stop syncing
```

Disconnect clears the selection and stops polling. Documents already synced stay in the store and
stay recallable. Remove them like any context document.

<Note>
  The token never crosses memloom's HTTP API or the viewer; the daemon reads it from its own
  environment. Page content goes only to your embedding provider, and only the changed parts.
  Notion webhooks need a public HTTPS endpoint, so a local-first daemon polls by design.
</Note>
