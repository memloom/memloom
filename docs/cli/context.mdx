## context add

```bash
memloom context add <path...>
```

Ingest files or folders, which recurse. Chunks embed into the same recall as memories and each
carries its breadcrumb, so results always say where they came from.

| Kind | Extensions |
| --- | --- |
| Text | `.md` `.txt` `.pdf` |
| Web | any `http(s)` URL |
| Audio | `.mp3` `.m4a` `.wav` `.flac` `.ogg` `.opus` `.aac` `.wma` |
| Video | `.mp4` `.mkv` `.mov` `.webm` `.avi` `.m4v` |

Documents are mirrors of their files: re-adding an unchanged one is a no-op, a changed one
replaces the chunks whose text changed and keeps the rest, and a pipeline improvement re-ingests
files whose bytes did not change.

Linking also starts watching. A folder keeps taking in files that appear in it later, which is what
makes pointing a recorder at a folder work. See [Watching files and folders](/guides/file-sync).

<Note>
  A file enters two ways: **linked** from disk with this command, or **uploaded** as a snapshot in
  the viewer. Linking is the stronger identity. Linking a file that was uploaded absorbs the
  upload; uploading one that is already linked is refused with a pointer to the document.
</Note>

Recordings are transcribed and diarized on this machine through the ingest queue. Run
`memloom audio setup` once first. See [Recordings](/guides/recordings).

## context list, context remove

```bash
memloom context list          # documents with ids and chunk counts
memloom context remove <id>   # delete a document and its chunks
```

The file on disk is untouched. An uploaded recording's snapshot in memloom's uploads directory is
deleted with it.

***

## context roots, watch, unwatch, forget

```bash
memloom context roots              # watched folders, document counts, last check
memloom context unwatch <path>     # stop syncing a folder or one file
memloom context watch <path>       # start again
memloom context forget <folder>    # drop it from the list, keep its documents
```

`watch` and `unwatch` take the path you linked, not an id, and work on a folder or a single file.
Nothing already learned is affected either way.

<Warning>
  `forget` and `remove` read alike and are not the same. `forget` drops a folder from the watch
  list and keeps every document it produced. `remove` deletes a document and its chunks.
</Warning>

`MEMLOOM_SYNC=off` disables watching for the whole daemon. Folders are still recorded, so it picks
up where it left off when switched back on.

## audio

```bash
memloom audio setup          # fetch the speech and speaker models, once per machine
memloom audio models         # the catalog: sizes, languages, what is installed
memloom audio use <id>       # transcribe with a different model from now on
memloom audio status         # selected model, installed models, ffmpeg
```

Models live in `~/.memloom/models` and are shared across projects. Transcripts are cached by file
hash and model, so re-adding a recording or switching back to a model you used before costs
nothing.
