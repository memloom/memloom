## Overview

Memories and ingested documents live in one graph, connected by the entities they mention. Your
saved belief "the ingest worker restarts via systemd" and the runbook you ingested both mention
**ingest worker**, so they sit two hops apart, and recall follows the same edges.

<CardGroup cols={2}>
  <Card title="Stored per chunk" icon="layer-group">
    Entity edges point at individual chunks, so the engine knows which section mentions what.
  </Card>
  <Card title="Shown per document" icon="file">
    The graph API rolls those up into one weighted edge, so a 300-page PDF is one node, not 300.
  </Card>
</CardGroup>

***

## What is in it

| Node | Comes from | In the viewer |
| --- | --- | --- |
| **Memory** | Active saved memories | Circle, coloured by type |
| **Entity** | `memloom index` extraction | Purple circle |
| **Document** | `memloom context add` | Emerald diamond |
| **Chunk** | Expanding a document node | Square |

| Edge | Meaning |
| --- | --- |
| `mention` | A memory or chunk mentions an entity |
| `replaces` | Version lineage: this memory superseded that one |
| `distinct` | A resolved *keep both*: related but deliberately separate |

Only active memories and edges appear. Stale versions and reverted resolutions drop out.

## Indexing

Indexing runs automatically a few seconds after you save a memory or add a file, debounced so a
folder ingest becomes one run. Saves stay fast because the model work never blocks them.

```bash
memloom auto-index off    # make indexing explicit again
memloom index             # run it now
memloom index --rebuild   # wipe extracted entities and start over
```

Extraction is precision-first: it would rather miss an entity than invent one.

<Steps>
  <Step title="Extract" icon="wand-magic-sparkles">
    One model call per row against a closed vocabulary of 9 entity types, capped at the 5 most
    salient entities. The prompt lists names already in your graph so the model reuses them.
  </Step>
  <Step title="Validate" icon="filter">
    A deterministic pass drops out-of-vocabulary types, math expressions, sentence fragments, and
    names under two letters. Formula-heavy chunks skip the model entirely.
  </Step>
  <Step title="Resolve" icon="link">
    Survivors resolve to a node by name key: casefolded, trimmed, leading `@` dropped. Folded-away
    spellings resolve too, so `Opus 4.8` lands on `Claude Opus 4.8`.
  </Step>
</Steps>

<Accordion title="Vocabularies and confidence" icon="book">
  Entity types: `person`, `organization`, `project`, `tool`, `technology`, `agent`, `place`,
  `event`, and `concept`, which is explicitly a last resort. `agent` means a named AI model or
  assistant that does work, the actor rather than the company that made it.

  The same call extracts typed relationships against a closed predicate list: `uses`,
  `depends_on`, `part_of`, `created_by`, `works_on`, `works_at`, `located_in`, `attended`.
  Out-of-vocabulary predicates and anything under 0.7 confidence are kept as plain `mention`
  edges.

  A node's identity is its name key alone. Type is an attribute, so an extractor that says
  `technology` today and `project` tomorrow cannot fork the node.
</Accordion>

<Warning>
  Extraction is not deterministic: the same input can extract differently on another run.
  `--rebuild` also needs a model, so running it offline still wipes, leaving everything unindexed
  until a key is configured. Belief edges are never touched by a rebuild.
</Warning>

## The schema

The vocabularies live in a registry, not in code. Edit them in the viewer's Schema tab, with
`memloom schema`, or at `GET /memory/schema`.

| Action | Effect |
| --- | --- |
| **Add** | A type or predicate of your own joins the prompt on the next run |
| **Propose** | The extractor asks for a missing type. Approve or dismiss it |
| **Disable** | Leaves the prompt. Entities already extracted under it stay |
| **Delete** | Only for disabled entries you added. Built-ins can only be disabled |

The description you write **is** the extraction rule, so write it like one: "a named drug or
supplement" rather than "medications". A proposal only surfaces after two independent extractions
asked for it.

## Managing entities

The Schema tab lists every entity with its usage counts and the tools to correct it.

| Action | Notes |
| --- | --- |
| **Rename** | Re-embeds under the new name. Renaming onto an existing name is refused, since that is a merge |
| **Retype** | To any active vocabulary type |
| **Merge into** | Moves every mention and relationship to the survivor, keeps an alias, fully revertable |
| **Delete** | Removes the entity and its edges. Refused while an unreverted fold points at it |

memloom can find the duplicates for you. See [Entity resolution](/concepts/entity-resolution).

## Traversal

```bash
GET /memory/entities/related?q=<name or id>&type=<entity type>
```

Walks out from one entity instead of returning the whole graph. Stated relationships come back
separately from entities that merely co-occur, because those are different kinds of evidence. In
the viewer it is the traverse panel on the Graph tab; agents use [`related_entities`](/mcp/tools).

## In the viewer

Click a document diamond to expand it into chunks with their real chunk-level edges. Click a chunk
to read it, with breadcrumbs back up. A document's panel has an **Open file** button.

<Note>
  The daemon only opens files it previously ingested, looked up by document id and never by a path
  from the request, so that button cannot be pointed at arbitrary files.
</Note>
