## Overview

A hosted memloom is the same server you run on your laptop, reachable from anywhere. Claude.ai,
Claude Code, Cursor and the memloom CLI all read and write one store, so what one tool learns the
others can recall.

This guide uses three services, each doing one job:

| Piece | Service | Holds |
| --- | --- | --- |
| Server | Fly.io, one `shared-cpu-1x` machine with 1 GB | memloom itself: the API and MCP at `/mcp` |
| Database | Neon (Postgres with pgvector) | Memories, documents, the graph, tokens |
| Recordings | Cloudflare R2 | Uploaded audio and video |

The machine keeps nothing that matters on its own disk. Replace it and it comes back with the
same memories from Neon and fetches recordings from R2 as they are needed.

Fly bills the machine for every hour it runs, about $7 a month for this size. Neon's and R2's free
plans cover a personal store. Any host that runs a Docker image and any Postgres with pgvector
work the same way; only the commands differ.

***

## What changes when memloom is hosted

Setting `MEMLOOM_PUBLIC_URL` turns a daemon into a hosted server:

- It listens on every interface, on `PORT`, instead of `127.0.0.1:4319`.
- Every request needs a token. The token decides whose memories it reaches; a header or body
  naming another owner is refused.
- Claude.ai can connect with OAuth: it opens a sign-in page that asks for `MEMLOOM_LOGIN_PASSWORD`.
- Routes that read the server's own disk are closed: adding local files and folders, folder
  watching, the import streams, and the admin routes. Recordings still arrive by upload.
- The viewer is not served. Run it locally against your own store.
- The MCP tools are the same, minus `add_file`, which takes a path on the server's disk.

## Deploying

<Steps>
  <Step title="Create the database" icon="database">
    Make a Neon project and copy its connection string. memloom creates its schema on first
    start, so there is nothing to run by hand.
  </Step>
  <Step title="Create the bucket" icon="bucket">
    In Cloudflare, create an R2 bucket and an API token with read and write access to it. You
    need the account's S3 endpoint, the bucket name, and the token's access key ID and secret.
  </Step>
  <Step title="Create the app" icon="rocket">
    From the repo root:
    ```bash
    fly launch --no-deploy        # keeps fly.toml, picks an app name
    ```
    `fly.toml` runs one machine that never stops, because a stopped machine takes seconds to
    answer the first recall.
  </Step>
  <Step title="Set the secrets" icon="key">
    ```bash
    fly secrets set \
      MEMLOOM_PUBLIC_URL=https://<app>.fly.dev \
      MEMLOOM_LOGIN_PASSWORD='<at least 12 characters>' \
      MEMLOOM_PG_URL='postgresql://...neon.tech/neondb?sslmode=require' \
      OPENROUTER_API_KEY=sk-or-... \
      MEMLOOM_S3_ENDPOINT=https://<account-id>.r2.cloudflarestorage.com \
      MEMLOOM_S3_BUCKET=memloom \
      MEMLOOM_S3_ACCESS_KEY_ID=... \
      MEMLOOM_S3_SECRET_ACCESS_KEY=...
    ```
  </Step>
  <Step title="Deploy" icon="play">
    `fly deploy`, then `curl https://<app>.fly.dev/health`. Anything else without a token
    answers 401.
  </Step>
</Steps>

<Warning>
  A hosted server needs `MEMLOOM_PG_URL`. Without it the store lives on the machine's disk and is
  gone when the machine is replaced.
</Warning>

## Connecting your tools

### Claude.ai

Add a custom connector with the URL `https://<app>.fly.dev/mcp`. Claude.ai registers itself,
opens the sign-in page, and asks for your login password. After that it refreshes its own access,
for up to 90 days without use.

Sign-in is limited to ten wrong passwords per address every 15 minutes.

### Claude Code, Cursor and other MCP clients

Create a token, then give it to the client:

```bash
MEMLOOM_PG_URL='postgresql://...neon.tech/...' memloom token create --label laptop
```

`memloom token` opens the database directly, so run it anywhere that can reach Neon. It prints
the token once.

```bash
claude mcp add --transport http memloom https://<app>.fly.dev/mcp \
  --header "Authorization: Bearer mlm_..."
```

Clients that take a JSON config use the same URL and header.

### The memloom CLI and hooks

Point the CLI at the server instead of a local daemon, in `~/.memloom/config.env` or the
environment:

```bash
MEMLOOM_URL=https://<app>.fly.dev
MEMLOOM_TOKEN=mlm_...
```

`memloom recall`, `save` and the rest go to the server and no local daemon starts. The Claude
Code hooks follow the same settings: prompt-time recall asks the server, and a finished session's
transcript is uploaded so the server can import it.

### Tokens

| Command | Does |
| --- | --- |
| `memloom token create [--label <name>]` | Print a new token. Shown once |
| `memloom token list` | Tokens that still work, with when each was last used |
| `memloom token revoke <id-prefix>` | Stop one working, at once |

Tokens are stored as hashes, so a lost one cannot be shown again. Revoke it and create another.
With `MEMLOOM_OWNER_ID` set, a token acts for that person; see
[memory per person](/guides/memory-per-person).

## Recordings

With the four `MEMLOOM_S3_*` settings, every uploaded recording is also written to the bucket.
The machine keeps a working copy for transcription and playback; a copy it has lost is fetched
back the first time something asks for it.

Transcription runs on the server, so its models load into the machine's memory. On a 1 GB
machine, long recordings may need a larger size; `fly scale memory 2048` changes it.

<Note>
  Deleting a document removes its file from the machine but not yet from the bucket.
</Note>

## Settings

| Setting | For |
| --- | --- |
| `MEMLOOM_PUBLIC_URL` | The server's public address. Turns on tokens and sign-in. Must be https except on localhost |
| `MEMLOOM_LOGIN_PASSWORD` | The Claude.ai sign-in password, at least 12 characters. Unset means no sign-in, tokens only |
| `PORT` | The port to listen on. Fly sets it from `fly.toml` |
| `MEMLOOM_S3_ENDPOINT` `MEMLOOM_S3_BUCKET` `MEMLOOM_S3_ACCESS_KEY_ID` `MEMLOOM_S3_SECRET_ACCESS_KEY` | The bucket for recordings. All four or none |
| `MEMLOOM_S3_REGION` | Default `auto`, which R2 expects. AWS needs the bucket's region |
| `MEMLOOM_URL` `MEMLOOM_TOKEN` | On a client: use this server instead of a local daemon |

To try hosted mode on your own machine, run `memloom-mcp --http` with
`MEMLOOM_PUBLIC_URL=http://localhost:8080` and `PORT=8080`.
