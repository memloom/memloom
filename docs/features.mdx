## Overview

One local store, several capabilities layered on it. Every card links to the page that explains
the mechanism.

<CardGroup cols={2}>
  <Card title="Belief pipeline on save" icon="filter" href="/concepts/memory-types">
    A save is not an insert. Duplicates merge, rewordings become versions, contradictions are kept
    and raised. Nothing is silently overwritten.
  </Card>
  <Card title="Hybrid recall" icon="magnifying-glass" href="/concepts/retrieval">
    Meaning, exact words, and entity anchoring, fused into one ranking over your memories and your
    files together.
  </Card>
  <Card title="Grounded assistant" icon="comments" href="/concepts/assistant">
    Chats over your store, answers only from what it found, and cites passages you can open.
  </Card>
  <Card title="Your files, cited" icon="file-lines" href="/guides/extractors">
    Markdown, text and PDF, chunked along real structure so a result is one section, not a blind
    window.
  </Card>
  <Card title="Recordings and web pages" icon="microphone" href="/guides/recordings">
    Audio and video transcribed and diarized on-device, cited by timestamp. Web pages fetched and
    parsed in-process.
  </Card>
  <Card title="One graph" icon="circle-nodes" href="/concepts/graph">
    Entities link memories and documents. The vocabulary is a registry you can extend, prune, and
    correct.
  </Card>
  <Card title="Entity resolution" icon="diagram-project" href="/concepts/entity-resolution">
    Folds duplicate spellings, asks about the uncertain ones, and keeps every fold reversible.
  </Card>
  <Card title="Version history" icon="clock-rotate-left" href="/concepts/memory-types">
    Every memory is a version chain. Nothing is destroyed, and `memloom history` walks it.
  </Card>
  <Card title="Conflicts you settle" icon="scale-balanced" href="/concepts/conflicts">
    When two memories cannot both be true, both are kept and you decide. Every resolution is
    reversible.
  </Card>
  <Card title="Reconciliation" icon="rotate" href="/concepts/reconciliation">
    The store reviews itself, repairs what SQL proves, and asks about the rest. Automatic runs
    never spend money.
  </Card>
  <Card title="Claude Code history" icon="file-import" href="/concepts/distillation">
    Import past sessions, or capture new ones continuously, distilled through the same pipeline
    with provenance back to the line range.
  </Card>
  <Card title="Local-first" icon="lock" href="/guides/self-hosting">
    The store is a folder. Copy it to back it up. The only network calls go to the provider you
    configure.
  </Card>
</CardGroup>

## Every client, one store

| Surface | For |
| --- | --- |
| **CLI** | You, in a terminal |
| **MCP** | Claude Code, Claude Desktop, Cursor: agents that save and recall as they work |
| **Viewer** (`memloom ui`) | Graph, assistant, memories, documents, schema, conflicts, console |
| **HTTP** (`127.0.0.1:4319`) | Scripts, editors, anything else |
| **Postgres wire** (`127.0.0.1:54329`) | Drizzle Studio or psql against the raw data |

All of them talk to one daemon that owns one store, so an agent's save is instantly visible in the
viewer and your CLI recall sees what the agent ingested. See
[Architecture](/concepts/architecture).
